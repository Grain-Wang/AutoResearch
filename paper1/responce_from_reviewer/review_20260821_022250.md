## 2. 🔄 改进效果评估

针对 `paper1/steps/` 和本轮回应，上一轮意见得到了明显且可审计的处理，但完成状态仍主要是 `DONE-DESIGN/SPECIFIED`，不能等同于实验完成。

- ✅ **有效改进**：
  - 唯一主线已锁定为 CoVoL-Depth，Q-GeoRoute 被严格停放为 Gate-0 失败后的备用 Phase 0，解决了两套任务栈并行导致的资源和叙事失焦。
  - 最近邻矩阵补入语言深度鲁棒性、Language as Prior、CapDepth、Learning-to-Defer 和 SelectiveNet，并明确撤回“错误语言危害、冻结视觉校准、细粒度文本、通用 gate”的新颖性主张。
  - 方法目标已收缩为控制视觉难度、候选差异和残差幅度后的文本—区域语义增量；A/B/C 嵌套 probe、交叉拟合 nuisance residual 和 H-semantic 停止条件直接回应了“普通 advantage gate 足以解释全部收益”的核心攻击。
  - `D0/D1` 的独立训练、冻结、哈希、离线缓存和 router 只读协议消除了 expert/router 联合漂移；16×16 区域、有效像素阈值、mean AbsRel 和上采样规则也已唯一化。
  - 删除 `L_sparse`，改为预注册 `κ=0.80` 的 clean-gain constraint，并将尾部风险写为 CVaR，方向上比“靠稀疏正则防止全关门”更可审计。
  - 干预数据协议区分 natural error 与 structured intervention，隔离 scene、template、captioner、词表和 held-out error family，并给出固定数量、schema、哈希和失败条件。
  - 新增步骤状态表，明确 `DONE-DESIGN` 不代表实验完成，并要求保留失败日志和 `GO/ITERATE/STOP`，研究过程可追踪性显著提高。

- ⚠️ **部分解决**：
  - 交叉拟合只写了概念步骤，尚未固定 `K`、scene-group fold、fold 内特征归一化、超参数选择位置、近零 advantage 的标签处理和最终阈值选择流程；不同实现仍可能产生明显差异。
  - H-semantic 目前主要依赖 `C-B AUROC ≥0.03`。AUROC 增量可以由大量损失差极小的 patch 驱动，却不一定转化为更低 regret；必须增加 C 相对 B 的实际 retention–CVaR 策略收益门禁。
  - natural-error slice 已被单列，但“标签/检测结果中没有实体”不等价于实体真实不存在。NYUv2/KITTI 的标注覆盖和检测漏检可能把真实实体误判为 hallucination，当前机器检查尚无精度验证协议。
  - 16×16 hard nearest-neighbor gate 适合作为 canary，但可能产生块状深度断裂。已有 8×8/16×16/32×32 敏感性要求尚未覆盖 hard gate 的边界伪影。
  - 指标清单较完整，但 `CVaR@20%` 的尾部单位、worst-of-3 的聚合顺序、coverage 的分母以及 `R(·)` 的具体定义未写成唯一公式；结果出现后可能发生口径漂移。

- ❌ **无效/偏离**：
  - `003_intervention_dataset.md` 从 NYUv2/KITTI 的 official test/validation pool 取样后再做 60/20/20 train/dev/test。即使声明“只用于 canary”，一旦 router、阈值或算法选择读取这些样本，后续官方 test 结果即不再是独立测试；另留正式 test set 也无法恢复对已查看官方测试集的无偏性。
  - 当前执行顺序写为 `003 → 004 → 005 → 006`，但 H-defect 定义为 `D1` 相对同一公平 `D0` 的 regret，而步骤 005 才构建公平 `D0/D1`。发布的 TR2M checkpoint 没有独立公平 `D0`，且文档禁止用 null caption 冒充 `D0`，因此“TR2M 权重可先用于 H-defect”与正式假设自相矛盾。
  - “所有 gate 参数量在主方法 ±10%”不能应用于 always-D0/D1、CLIP similarity 和 `|D1-D0|` 等零参数启发式基线。更关键的是，standard L2D 是否读取与 C predictor 完全相同的文本—区域语义特征未声明；若 L2D 只读 B 特征，主方法优势无法区分“更多输入信息”和“新决策算法”。
  - 当前实现阻塞被正确记录，但尚未给出解除阻塞的确定动作。继续等待 TR2M 训练代码会使研究停留在协议层，不能形成强 CCF-C 证据链。

## 3. 🔍 强CCF-C维度深度审查

- **问题与动机**：
  - 问题已收缩为“自动 caption 出现局部、可机器验证语义错误时，在两个冻结 metric-depth 候选间逐区域选择”，清晰度已达到强 CCF-C 方案设计要求。
  - 当前动机仍依赖一个未验证前提：真实自动 caption 中可机器确认的局部实体/深度关系错误是否具有足够出现频率和足够深度损害。若最终只有模板化 structured errors 上成立，论文可成为受控鲁棒性研究，但不能写成普遍真实部署问题。
  - natural error 的“发生率”和“严重度”应分别测量。低发生率但高尾部风险可以支持风险论文；高发生率但无相对 `D0` 退化则不能支持候选路由必要性。

- **技术完备性**：
  - `D0/D1` 是整个定义的地基。当前上游阻塞意味着 H-defect、H-semantic 和 H-decision 均无法按正式定义执行。应直接实现仓库自有的 shared-backbone dual-head 基线，而不是把 TR2M 发布权重当作正式双候选。
  - cross-fitted semantic residual 与 clean-gain-constrained CVaR 都是可复用的标准统计/风险工具。强 CCF-C 的方法主张必须落在一个明确算法框：输入特征、fold 划分、nuisance 训练、residual target、primal-dual 更新、阈值校准和推理均有唯一伪代码，并通过同特征 L2D-C 与 risk-aware L2D-C 对比证明不是常规模块叠加。
  - advantage 的符号标签没有 margin。`a_p≈0` 的 patch 会对 AUROC 产生不稳定标签，尤其在不同深度有效像素数和传感器噪声下。应从重复推理/数值误差或 GT 有效像素扰动估计 tie band，并将连续 advantage 回归作为主诊断。
  - binary hard grid 路由保证了候选可解释性，但 nearest-neighbor 上采样可能制造块边界。若最终方法仍使用 hard gate，必须报告边界区域误差和非目标区域泄漏。

- **实验可信度**：
  - 所有 router 拟合、阈值选择和方法选择必须只使用 official training pool 内按 scene 划分的 train/dev；official benchmark test 在最终方法和超参数冻结前不得被读取。
  - 基线公平性应按类型处理：零参数 heuristic 原样运行；可训练 gate 匹配可训练参数、训练步数和超参数搜索预算。standard L2D-C 必须读取与主方法相同的全量语义特征，standard L2D-B 才用于测量语义信息增量。
  - H-semantic 不能只看分类指标。C predictor 必须在 held-out scene、held-out captioner 和 held-out error family 上，相对 B predictor 改善实际策略的 clean-gain–CVaR Pareto，且图像级 CI 不跨 0。
  - natural error 的机器 oracle 必须验证高精度。无法证明“实体不存在”的记录应标成 `unverified_mention`，不能计入 hallucination prevalence；KITTI 稀疏标签尤其不能直接当作完整实体清单。
  - `CVaR@20%` 应先在每图的 caption variants 上形成图像级风险，再跨图像统计，或明确采用另一种唯一顺序；禁止在 patch 级把相关区域当独立样本放大显著性。

- **叙事克制性**：
  - 因果、安全、首次和细粒度文本等 overclaim 已被系统移除，本轮写作克制性是明确优点。
  - 当前应继续把“语义增量可预测”视为科学假设，把“交叉拟合+约束式 CVaR router”视为未验证方法。两者不能合并成一个已成立贡献。
  - 即使 H-semantic 通过，也只能说明语义特征含增量信息；只有在同特征、同容量、同搜索预算的 L2D-C 上取得更优风险—收益前沿，才支持算法贡献。

## 4. ⚔️ 模拟评审攻击 (Top 3 Rejection Risks for Strong C-C)

1. **“方案写得严谨，但依然没有一项可运行证据，且核心双候选基线尚未存在。”**
   - 攻击依据：`003` 仍是 `SPECIFIED, NOT EXECUTED`；004/005 被阻塞；仓库没有 JSONL、checkpoint、结果表或脚本。
   - 现有内容能否扛住：**不能。** 研究设计成熟度提高不能替代缺陷复现和公平候选的训练成功。

2. **“数据协议污染官方测试集，natural-error 标签又可能来自不完整标注/检测漏检。”**
   - 攻击依据：官方 test/validation 样本被重新划为 router train/dev/test；实体 absence 规则没有证明 annotation/detector coverage。
   - 现有内容能否扛住：**不能。** 这会同时破坏结果独立性和真实错误标签可信度，属于强 CCF-C 的致命实验设计问题。

3. **“主方法仍是带语义特征的标准 L2D，加了 cross-fitting 和 CVaR；基线若拿到同样输入和风险目标可能完全复现收益。”**
   - 攻击依据：cross-fitting、residualization、coverage constraint 和 CVaR 均非本任务专属机制；当前未定义 same-feature L2D-C/risk-aware L2D-C。
   - 现有内容能否扛住：**不能。** 必须通过同特征、同容量、同训练预算的直接对比和组件消融回答，而不能依赖命名差异。
