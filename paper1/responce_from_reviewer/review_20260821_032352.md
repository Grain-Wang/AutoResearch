# Review 2026-08-21 03:23:52 UTC

## 1. 🎯 强CCF-C达标判定
- **当前状态**：未达标
- **核心差距**：上一轮的测试集污染、缺陷复现顺序和同特征 L2D 公平性已被修正，但当前仍无真实数据或科学结果；更关键的是，现有协议让 expert 与 router 共用同一训练图像，且 Claim-F 的 `C-B` 比较同时改变语义输入与 residualization 算法，未来即使取得正结果也无法唯一归因于“语义增量”或“新路由机制”。
- **C类顶流潜力**：否。当前已具备扎实强 CCF-C 项目的研究审计意识和可证伪框架，但最新直接近邻已经覆盖 leave-one-out 模态贡献监督、像素级 dense deferral、连续回归 deferral 和冻结专家的 post-hoc defer；若最终方法只是 cross-fitting、CVaR 与区域 gate 的任务化组合，即使实验为正，也更接近常规强 CCF-C，而不具备 Best Paper Nomination 所需的独立机制突破。

## 2. 🔄 改进效果评估

针对 `paper1/steps/`、新增基础代码和 `response_20260821_022250.md`，上一轮意见得到了实质回应。本轮修改不再只是文字重述，已经出现可运行的数据切分与指标代码；但科学证据仍为零，若干新设计问题必须在首轮 GPU 实验前修正。

- ✅ **有效改进**：
  - official benchmark test 已从开发流程中移除。`build_image_manifest.py` 只从 official training pool 选择内部样本，对 image ID 和 scene ID 与 official test 的交集执行硬失败，并用 scene hash 生成确定性切分；对应测试覆盖确定性、scene 隔离和官方测试 scene 泄漏。
  - `H-sensitivity` 与 `H-fallback-defect` 已拆分，正式执行顺序改为 `003 → 005 → 004-B → 006`。TR2M released checkpoint 只允许作 clean→corrupt 敏感性诊断，不再被误写成公平 `D1 vs D0` 缺陷证据。
  - 不再等待 TR2M 训练代码，步骤 005 锁定仓库自有 shared-backbone dual-head 路线，并明确冻结、哈希、缓存和梯度隔离要求，工程阻塞已经转化为可执行任务。
  - Claim-F 与 Claim-M 已分开。Claim-F 需要分类增量和策略效用双门；Claim-M 只能由 Main 相对 same-feature、same-objective、same-budget `Risk-L2D-C` 的比较支持，避免用“语义可预测”替代“方法有创新”。
  - baseline contract 正确区分零参数 heuristic 与 learned gates；`L2D-B/L2D-C/Risk-L2D-C/Main` 的输入、目标、参数和 trial 预算已机器可读化。
  - 指标口径已经显著收敛。variants 先在图像内聚合，CVaR 使用图像级 worst positive regret，coverage 明确 eligible-region 分母，clean gain 无显著正增益时触发 STOP；现有 7 个单元测试与文档声称的测试数量一致。
  - 16×16 hard gate 不再被默认视为最终设计，步骤 009 已预注册 global/8×8/16×16/32×32、hard/soft 和边界带误差分析。
  - 组件级近邻已经承认 DML、orthogonal learning、CVaR 和 risk control 均非独立创新，叙事克制性继续保持较高水平。

- ⚠️ **部分解决**：
  - `build_image_manifest.py` 能验证用户提供的 `image_id/scene_id`，但尚无 NYUv2/KITTI 数据适配器、原始 RGB 内容哈希、相邻帧规则或真实 `split_audit.json`。若 manifest 的 scene 定义错误、同一帧使用不同 ID，当前测试仍会给出 PASS。
  - 当前 D0/D1 协议仍存在输入不对称：D0 使用 image global context，D1 使用 caption context。虽然两者都读取 frozen multi-scale image features，但 D1 相对 D0 同时“加入文本”并“移除 image-global context”，无法把候选差异唯一归因为语言。
  - 5-fold scene-group cross-fitting 固定了 outer fold、trial 和 scaler 边界，但 residual target 的训练过程仍不完整。文档没有写出如何在 outer-train 内生成每个训练样本的 nuisance OOF prediction，也没有写出 outer-fold 评估后最终模型如何聚合超参数并在全 train 上重拟合。
  - core metrics 已实现，但 official crop/valid-depth 处理、AUROC、paired/cluster bootstrap、置信区间和真实结果表尚未实现。当前 `metrics.py` 接收预计算 loss，尚不能独立保证 NYUv2/KITTI 官方指标口径。
  - natural-error 协议比上一轮严格，但 `verified-clean` 仍过强。现有 predicate 只能证明“未检测到预注册的实体/远近冲突”，不能证明整条 caption 真实无误，后续应使用 `predicate-clean` 或 `no-verified-error`。
  - predicate validity 使用程序化正负例时容易形成循环验证：用同一 GT 规则生成错误，再用该规则验证，只能证明代码实现一致，不能证明自然 caption error detector 的 precision。
  - held-out captioner 在每个数据集只有 100 张 internal-test 图像。要满足每个 `dataset×captioner×predicate` 至少 30 个 verified natural errors，错误发生率需非常高；当前没有样本量或 power 计算，真实错误主张很可能天然欠功效。
  - hypervolume reference 的当前定义取 dev 上 always-D1 与全部候选方法 CVaR 的最大值再加 margin。加入一个极差候选会改变 reference point，从而改变全部方法的 hypervolume；reference 应独立于待比较候选。

- ❌ **无效/偏离**：
  - 步骤 005 用内部 `train` split 训练 D0/D1，步骤 006 又在同一 `train` split 上构造 advantage 并训练 router。meta-router 因而读取 expert 的训练内预测，属于 stacking 层面的信息泄漏；当前 cross-fitting 只作用于 nuisance/router，不作用于 expert predictions。
  - 300 张/数据集既承担 expert 训练又承担 router 训练。对 metric-depth calibration head 而言样本过少，同时会放大 expert 过拟合产生的伪 advantage。最终 internal-test 虽独立，但 router 的训练标签仍可能是训练内误差结构，导致结果不稳定且难以复现。
  - Claim-F 的 `C-B` 不是纯语义增量实验。B 是直接 advantage predictor，C 同时加入 semantic features 和 cross-fitted residualization；若 C 更好，无法判断收益来自文本信息还是训练算法。当前 Claim-F 与 Claim-M 的拆分在叙事上正确，在实验变量上尚未真正正交。
  - 最近邻审计仍遗漏四项直接工作：MRUF (`arXiv:2607.10599`) 已用 leave-one-out error increase 监督多粒度模态路由；DeferredSeg (`arXiv:2604.12411`) 已提出像素级 dense L2D 与 spatial-coherence routing；Regression with Multi-Expert Deferral (`arXiv:2403.19494`) 已覆盖连续损失和 two-stage deferral；Density-Ratio Losses for Post-Hoc L2D (`arXiv:2605.19557`) 直接面向冻结模型/专家和可调 deferral threshold。这些工作分别覆盖当前“经验贡献教师、区域路由、回归 defer、冻结候选后处理”的关键部件。
  - 当前 baseline contract 只覆盖 gate。上一轮要求的 caption dropout、corruption augmentation、multi-caption ensemble/consistency 等 expert-level robust baselines 未进入最新步骤 007；若简单鲁棒训练使 D1 不再受错误 caption 影响，两候选 router 的必要性会被消除。
  - `target_deletion` family 把局部实体删除、远处实体删除和完整 null caption 放在同一个三变体组。worst-of-3 和 CVaR 可能完全由 null caption 主导，之后却被解释为“局部删除风险”，属于实验语义混写。
  - current `zC` feature contract 没有显式禁止 `error_type/template_id/generator/variant_id/machine_check` 等干预元数据进入 router。只检查 L2D-C 与 Main 列相同，无法阻止所有方法共同利用模板标签泄漏。

## 3. 🔍 强CCF-C维度深度审查

- **问题与动机**：
  - 主问题已经足够清晰：自动 caption 出现局部、机器可验证错误时，在冻结的纯视觉和图文 metric-depth 候选间作区域选择。范围清晰度已达到强 CCF-C 方案阶段要求。
  - 当前最弱的一环从“问题过宽”转为“问题是否在真实数据中足够常见”。Qwen2.5-VL、InternVL3 等较强 captioner 的 GT-decidable entity/depth-relation 错误可能很少；100 张 held-out 图像不足以稳定估计 prevalence 与 tail regret。
  - NYUv2/KITTI 与局部错误 oracle 的兼容性尚未证明。KITTI 深度稀疏，且 Eigen-style depth 数据本身不提供完整 instance mask；“每个实体 mask 至少 32 个有效深度像素、实体对深度差至少 10%”可能导致远处/小目标几乎全部失效。应先做 annotation-coverage canary，再承诺 12,000 条干预。
  - 若最终只有 structured templates 上存在风险，而 natural errors 样本不足，论文仍可报告受控鲁棒性，但动机必须限定为“可验证干预压力测试”，不能外推自动 caption 部署安全性。

- **技术完备性**：
  - 公平 D0/D1 应体现“D1 在 D0 相同视觉信息基础上增加文本”，而不是用 caption context 替换 image-global context。最干净的结构是两者都接收相同 image-global feature，D0 的 text channel 使用固定 null/zero embedding，D1 使用真实 caption embedding，其他层逐项同构。
  - 独立训练两个 heads 会产生随机优化差异。必须增加两个 image-only twin heads 以及 shuffled-caption D1 作为负控制，测量 router 是否只是利用随机 expert diversity，而非语言语义。
  - router 属于二层 stacking。训练 meta-model 时必须使用 OOF expert predictions，或使用与 expert-train 完全 scene-disjoint 的 router-train。当前只对 router 内 nuisance 做 cross-fitting，不能消除 expert 训练内预测偏差。
  - Claim-F 应固定为同一模型、同一目标下的 `B-direct(zB)` 对 `C-direct(zC)`，并增加 scene-wise permuted semantic features。orthogonalized Main 只能进入 Claim-M；否则信息增量与算法增量无法分离。
  - 当前 residualization 伪代码缺一个 inner cross-fit：outer-train 中每个 residual target 都必须来自未见该样本的 nuisance model。需要明确 outer 5-fold、inner 4-fold、trial 选择、final refit 和每个样本唯一预测的完整状态机。
  - hypervolume reference 必须在查看候选方法前固定；bootstrap replicate 内要重新计算 clean-gain denominator、retention、CVaR 和 hypervolume，不能只对最终点做近似重采样。

- **实验可信度**：
  - NYUv2 scene 和 KITTI drive 内的多帧高度相关。置信区间不能一律 image-level bootstrap；应按 `scene_id/drive_id` 做 cluster bootstrap，保留同 scene 的全部图像与 caption variants，否则显著性会被夸大。
  - 当前 100 张/数据集 internal-test 是否足以检测 `ΔAUROC=0.03` 和 hypervolume 差异未知。必须在训练前用 scene 数、错误发生率和 pilot variance 做功效模拟；power 不足时应扩大内部测试场景，而不是依赖 patch 数量制造窄 CI。
  - 直接 baseline 至少应包括：continuous two-stage regression deferral surrogate、post-hoc density-ratio defer、dense spatial-coherence defer、MRUF-style leave-one-out contribution router，以及 standard L2D-C/Risk-L2D-C。否则 Claim-M 只打赢自定义弱基线。
  - expert-level killer baselines 应单独匹配 backbone、数据和训练步数：caption dropout、结构化 corruption augmentation、multi-caption ensemble、图文 consistency filtering。它们不能强行读取同一 frozen cache，但必须使用公平训练预算。
  - structured error 测试需加入 text-only artifact classifier 和 frozen VLM contradiction/grounding scorer。若纯文本模板识别器即可达到 Main 的 Pareto，论文不能声称发生了图文几何可靠性推理。
  - official-test one-shot 原则是正确的，但正式测试 captioner、prompt、revision 和 clean/error 审计也必须在打开 official test 图像前冻结，否则 caption 生成过程本身仍会成为测试集调参通道。

- **叙事克制性**：
  - 现有文档对“无因果、无安全保证、无首次、标准组件非创新”的处理正确，应继续保留。
  - `verified-clean` 应改成 `predicate-clean`；`natural error precision` 只能覆盖被审计的 predicate，不能写成完整 caption factuality。
  - DeferredSeg 已覆盖像素级 dense deferral，MRUF 已覆盖 error-increase modality routing，因此“区域 defer”和“任务误差贡献教师”不能再作为新颖性。Claim-M 只能表述为特定于冻结深度候选、clean-retention/tail-regret 双目标的决策过程，并且必须显著超过上述直接方法。
  - 即使 Claim-F 成立而 Claim-M 失败，一篇“语义条件增量可预测性”分析型论文可能达到普通 CCF-C，但不应继续包装成新算法论文；这一路径应在状态表中预先写明。

## 4. ⚔️ 模拟评审攻击 (Top 3 Rejection Risks for Strong C-C)

1. **“你们用 expert 的训练内预测训练 meta-router，这只是会过拟合的 stacking；300 张图训练出的两个 heads 还会制造大量随机伪 advantage。”**
   - 攻击依据：步骤 005 与 006 共用内部 train split，expert cache 没有 OOF/expert-disjoint 要求；D0/D1 又独立随机训练。
   - 现有内容能否扛住：**不能。** internal-test 独立只能检验最终结果，不能证明训练目标没有被 expert 过拟合污染，也不能解释语言特异性。

2. **“C 相对 B 同时增加语义特征和 orthogonal residualization；更何况 MRUF、DeferredSeg、regression deferral 和 post-hoc L2D 已覆盖主要机制。”**
   - 攻击依据：Claim-F 的变量未隔离；最近邻矩阵缺少最直接的多粒度模态路由、dense defer、连续回归 defer 和冻结专家 defer。
   - 现有内容能否扛住：**不能。** 必须使用 direct-C/direct-B、permuted semantic control 和上述直接算法基线后，才能判断剩余差异。

3. **“真实任务证据不足：所谓 clean caption 并未完整验证，100 张 held-out 图像大概率凑不出 30 个自然错误，KITTI 的稀疏深度也难以支持局部关系 oracle；显著性还按相关图像而非 scene 计算。”**
   - 攻击依据：natural-error 样本量无 power 计算；predicate validation 可能循环；局部 mask/depth 可用率未知；统计单位仍主要写 image-level。
   - 现有内容能否扛住：**不能。** 在 annotation-coverage、natural-error prevalence 和 scene-cluster CI 出现前，真实部署动机仍是未验证假设。
