## 2. 🔄 改进效果评估

针对上一轮 `review_20260821_032352.md`，本轮回应是实质性修改，不是简单复述。新增的 OOF 计划、cluster bootstrap、feature schema 与测试已经提高了后续实验的可审计性；但它们目前主要证明“计划文件内部自洽”，尚不能证明真实模型按计划训练。

- ✅ **有效改进**：
  - `build_image_manifest.py` 已把 sequence ID、frame index 和 RGB 内容 SHA256 纳入切分审计，并对 official test 的 image/scene/sequence/RGB overlap 执行硬失败；这比只比较文件名或 image ID 更可靠。
  - `cache_oof_experts.py` 明确区分 router-train 的 OOF experts 与 dev/internal-test 的 final experts，并禁止 prediction scene 出现在对应 training-scene hash set 中，正面解决了上一轮指出的 stacking 训练内预测污染。
  - Claim-F 已改为同目标的 `B-direct/C-direct/C-permuted`，Main-orth 不再参与语义信息判定；科学发现与算法贡献在实验变量上比上一轮更接近正交。
  - `features.py` 已禁止 `error_type/template_id/generator/variant_id/split` 等干预元数据及其显式派生列，且为列级 provenance 生成稳定 schema hash。
  - `bootstrap.py` 已按 scene/drive 成簇重采样，并在 replicate 内重新计算 retention、CVaR、Pareto front 与 hypervolume；这比对最终表格数字做 image-level bootstrap 更可信。
  - hypervolume reference 已改为只依赖 dev 上 always-D1 CVaR，不再随待比较候选集合变化。
  - 数据协议将 `verified-clean` 改为 `predicate-clean`，把 null caption 从局部 deletion family 中分离，并在局部标注不足时预注册 Virtual KITTI 2 退路，叙事更克制。
  - 直接基线已覆盖 regression deferral、density-ratio post-hoc L2D、dense coherence 和 leave-one-out uncertainty；robust single-expert killers 也重新进入正式门禁。

- ⚠️ **部分解决**：
  - OOF 审计目前只校验 JSON 中声明的 scene hash 和 64 位缓存 hash；它没有验证真实 checkpoint 文件、训练配置、训练 manifest、代码 commit 与 seed 是否对应，也不能证明模型实际未见 prediction cluster。
  - OOF plan 以 `scene_id` 分 fold，而数据切分以更严格的 `sequence_id/drive` 隔离。若同一 sequence 下存在多个 scene ID，train/prediction 仍可在 OOF 阶段共享近邻帧。
  - `build_stacking_plan` 默认把 official-training 中除 dev/internal-test scene 外的全部 scene 纳入 expert 训练，但步骤 003 只为选中的 pilot 图像生成 predicate-clean caption 与干预数据。D1 对未生成 caption 的训练图像没有定义，数据合同与训练合同尚未闭合。
  - D0/D1 的层名和参数量相同是必要条件，但 D0 的 zero text input 可能使 text adapter 的大部分权重永远收不到有效梯度；形式参数相同不等于有效容量相同。
  - Claim-F 声称 B-direct 与 C-direct 模型类和参数量完全相同，但 `z_C` 比 `z_B` 多语义列。若直接改变第一层输入维度，参数量必然不同；当前没有 zero-padding、固定投影或特征 masking 的唯一实现。
  - scene 内 cyclic caption permutation 可能仍保持正确局部语义，特别是 NYUv2 视频近邻帧和 KITTI 同一 drive 中的重复物体；它不是可靠的“语义被破坏、风格保持不变”负控制。
  - direct published-method adaptations 目前只有方法名和 objective 标签，没有原论文公式到本任务变量的逐项映射。强制所有 adaptation 与 Main 参数量 ±10% 还可能破坏原方法忠实性。
  - 22 个 toy/unit tests 对协议代码有价值，但没有 CI run、锁定环境日志或真实 NYUv2/KITTI fixture；本地通过不能替代可重复执行证据。

- ❌ **无效/偏离**：
  - `expert_stacking_plan.json` 的 prediction key 只有 `(dataset,image_id)`，expert ID 只有 `dataset:oof:fold/final`；当前 schema 无法在一个可审计 manifest 中同时表达 seeds `17/29/43`、D0/D1、image-only twins、shuffled-caption control 和不同 checkpoint。若每个 seed 单独建 manifest，现有文档与 expected artifact 又没有声明该层级。
  - `validate_expert_cache_manifest` 只检查 `d0_cache_sha256/d1_cache_sha256` 是 64 位十六进制字符串，不检查对应文件存在、内容 hash 相符、checkpoint SHA 或 training-scene manifest。该检查可被一个自洽但虚假的 manifest 通过。
  - feature denylist 只阻止 intervention metadata，没有阻止 `ground_truth/depth_gt/advantage/a_p/d0_loss/d1_loss/oracle/target` 等标签泄漏；一个改名后的 GT 派生特征仍可被声明为 `candidate` 并通过。
  - `bootstrap.policy_hypervolume` 以 `clean_gain_ci_lower=math.inf` 绕过 clean-gain 门禁。某些 cluster bootstrap replicate 中若 `mean(D0-D1)≤0`，函数会抛出 `STOP_NO_CLEAN_GAIN` 并中断整次 bootstrap；现有测试只使用每个 scene 都有相同正 clean gain 的理想样例，未覆盖这一真实情形。
  - 当前 Primary Claim 仍把 Main 称为 `orthogonalized`。现有算法只是 cross-fitted partial residual target；没有给出 Neyman-orthogonal moment、对 nuisance 扰动的一阶不敏感条件或相应损失，因此“orthogonalized”可能构成统计术语误用。
  - 最新直接近邻 [TIGER: Task-Instructed Causal Routing of Vision Foundation Models for Multi-Task Learning](https://arxiv.org/abs/2606.15765) 尚未进入 related-work audit。该工作使用自然语言任务指令、冻结异构视觉专家、token-level dense routing 和基于排除专家预测变化的贡献对齐，并在 NYUD-v2 等 dense benchmark 验证，直接压缩“语言条件 + 冻结专家 + dense contribution routing”的剩余空间。

## 3. 🔍 强CCF-C维度深度审查

- **问题与动机**：
  - 问题已足够清晰：在自动 caption 发生局部、可验证错误时，从纯视觉和图文 metric-depth 候选中逐区域选择。当前不再混入用户指令、GT caption 或通用 VLM 安全，符合强 CCF-C 的窄问题要求。
  - 尚未证明真实 natural-error 既有足够发生率，也有相对公平 D0 的实际 regret。若最终只能在 structured intervention 上成立，论文题目、摘要和贡献必须限定为“受控 caption stress test”，不能继续暗示真实部署常见风险。
  - KITTI 局部 mask/depth coverage 失败时切换 Virtual KITTI 2 是合理止损，但当前 Claim-F/Claim-M 仍写成必须在 NYUv2/KITTI 两数据集通过。数据替换后，到底是“NYUv2+VKITTI2 的局部路由”还是“KITTI image-level fallback”，尚未形成唯一主张。

- **技术完备性**：
  - OOF 是必要修正，但真实训练依赖尚未闭环。必须先回答：每个 OOF expert 使用哪些图像、这些图像的 predicate-clean caption 从哪里来、每个 seed/control 的 checkpoint 如何映射到 cache row。
  - D0/D1 的公平性需要“有效路径”而非只看参数总数。D0 应使用固定但非零、可通过同一路径传播的 learned null embedding，或者另给 shared-head text/no-text control；同时报告每个模块的 active-gradient parameter count。
  - Claim-F 需要纯粹的信息增量实验。B/C 应使用相同输入维度、相同第一层和相同参数量，唯一差异是 semantic block 被真实值填充还是被 mask；C-permuted 还需要证明局部 grounding 被破坏，而 caption 长度、风格和全局场景相似度没有被破坏。
  - Main 的训练目标尚未写成可实现数学定义。需要固定 CVaR 的 Rockafellar–Uryasev auxiliary variable、image/variant/region 聚合位置、clean constraint 的 Lagrange multiplier 更新、batch estimator、score-to-gate 映射与推理复杂度。否则 `Risk-L2D-C` 与 Main 的“same objective”无法验证。
  - 当前 residualization 不足以称为 orthogonal learning。除非给出正交 score，否则应改名为 `cross-fitted partial-residual router`，并把 DML 只作为启发来源。
  - 最新 TIGER 近邻使“排除专家后的误差变化教师”也不再独特。剩余方法边界必须落在一个任务专属决策问题上，例如固定 clean-utility 下的局部尾部 regret 约束，而不能继续依赖 contribution teacher 或 dense routing 本身。

- **实验可信度**：
  - 当前 point metric 是 image-weighted，置信区间却以 scene/drive 为 cluster。对于帧数差异很大的 sequence，一个长 drive 会在 point estimate 中占更大权重。论文必须预注册 image-weighted 还是 scene-macro estimand，并同时报告另一种作为敏感性分析。
  - retention 是两个平均差值之比。当 clean D1 gain 虽显著但数值极小时，ratio 和 hypervolume 会被任意放大。仅要求 CI 下界 >0 不足以保证数值稳定；还需要最小实际 clean-gain 门禁。
  - Claim-M 的主目标是 retention≥80% 下控制尾部 regret，因此最直接的主判据应是“dev 选择满足 80% retention 的 threshold，internal-test 比较该 threshold 下的 CVaR/worst-of-3”。全曲线 hypervolume 可作为次指标，否则低 retention 区域也可能贡献面积并改变结论。
  - bootstrap 对 ratio denominator 非正 replicate 的处理尚未定义；不能静默丢弃，也不能在第一个异常 replicate 直接崩溃。必须报告 denominator instability 比例并设置停止规则。
  - C-permuted 的构造需要两个负控制：风格/长度匹配但局部实体错配，以及保持全局场景相似但局部关系错配。单一 scene 内 permutation 既可能没有破坏语义，也可能因可置换 scene 太少而严重欠功效。
  - published baselines 必须区分 `faithful adaptation` 与 `capacity-matched adaptation`。只做后者可能把原方法裁剪弱化；只做前者又不能排除容量差异。主表至少需同时给出原公式忠实版和容量匹配版。
  - 当前 code tests 没有真实 crop/mask/metric adapter，也没有 source data fixture。第一轮 GPU 前应先以 20–50 个真实样本运行 end-to-end smoke test，验证 manifest→caption→expert→cache→metric 的文件链条。

- **叙事克制性**：
  - `predicate-clean`、Claim-F/Claim-M 分离、structured-only 降级和不使用“safe/causal/first”均是明显优点。
  - `orthogonalized` 是当前剩余最危险术语；如果没有正交 moment 和理论条件，应从标题、方法名、贡献列表和 baseline contract 中全部删除。
  - 即使 Main 击败若干 baseline，也只能主张“在本任务和预注册风险约束下获得更优经验前沿”。当前没有理论保证，不能写“非退化”“风险可控保证”或“可靠性保证”。
  - 若 TIGER、MRUF、DeferredSeg、regression/post-hoc L2D 的忠实 adaptation 已覆盖主机制，组合实验优势可以支撑普通强 CCF-C，但不应包装为新范式或 C 类 Best Paper 级突破。

## 4. ⚔️ 模拟评审攻击 (Top 3 Rejection Risks for Strong C-C)

1. **“新算法仍然不存在：TIGER/MRUF 已有贡献教师和语言/模态路由，DeferredSeg 已有 dense defer，regression 与 post-hoc L2D 已有冻结连续专家；你只组合了 partial residual、CVaR 和 coverage constraint。”**
   - 现有内容能否扛住：**不能。** 当前没有唯一损失函数、算法伪代码、复杂度分析或正结果；`orthogonalized` 也没有严格定义。即使未来结果为正，若只超过弱 adaptation，仍会被判为常规模块组合。

2. **“所谓 OOF 公平性只是 manifest theater：计划文件没有 seed/control/checkpoint 维度，hash 不绑定真实文件，OOF 又按 scene 而非 sequence/drive 划分，D1 的大部分 expert-training 图像甚至没有定义好的 caption。”**
   - 现有内容能否扛住：**不能。** 单元测试只能证明手写 metadata 自洽，不能证明真实模型训练历史。必须让训练脚本生成 manifest，而不是允许人工填写 manifest 后再验证。

3. **“Claim-F/Claim-M 的正结果可能来自控制和指标设计：B/C 输入维度不同、scene permutation 没有真正破坏语义、GT 派生列未被 denylist 阻断、tiny clean gain 又把 retention/HV 放大。”**
   - 现有内容能否扛住：**不能。** 当前四项都有明确实现缺口；其中 bootstrap 在非正 denominator replicate 上还存在可复现的失败路径。
